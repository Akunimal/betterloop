# MCPation browser-native delivery handoff

## Product contract

- MCPation is a WebMCP-native MCP configuration cleaner, not a locally installed service.
- The visible page asks the user to select an environment folder. Direct-access browsers use File System Access; Codex's embedded browser uses a read-only directory import.
- Analysis runs client-side and checks only known relative MCP configuration paths.
- WebMCP tools return sanitized metadata, findings, recommendations, access scope, and a supervised plan.
- Deterministic JSON cleanup requires visible selection and confirmation; a sibling backup is written first.
- TOML, JSONC, policies, commands, and ambiguous conflicts remain manual.

## Current implementation

- `src/mcp-files.ts` owns browser permission, persisted directory handles, known-path discovery, rescanning, backups, and supervised writes.
- `src/mcp-analysis.ts` is a pure parser and diagnosis engine for JSON, JSONC, and Codex TOML.
- `src/mcpation.ts` registers seven browser-native WebMCP tools.
- `scripts/mcpation-tests.ts` verifies parsing, duplicate detection, invalid URLs, disabled entries, coverage gaps, redaction, and safe write proposals.
- No daemon, extension, Gemini/model API key, localhost port, or install command is part of the product flow.

## Safety language

- Say “configured”, never “live” or “available”, because files do not prove runtime state.
- Say “browser-granted folder”, never “full disk access”.
- Do not apply a fix in the demo; stop at the supervised plan.
- Do not claim that WebMCP itself bypasses browser permissions.

## Remaining delivery checks

1. Validate the read-only directory import in the WebMCP in-app browser with an explicit user-selected folder.
2. Confirm seven production tools register and no console errors occur.
3. Rebuild Graphify after the browser-native refactor.
4. Commit, push, deploy, and record the under-three-minute demo.
