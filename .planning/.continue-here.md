# MCPation delivery handoff

## Product contract

- MCPation is a browser-native WebMCP Codex Environment Doctor, not a local companion or installed service.
- The user grants one workspace folder through the browser. The page never claims full-disk access.
- Discovery is bounded and allowlisted: Codex/MCP config, package manifests/locks, `AGENTS.md`, `AGENTS.override.md`, and `skills/**/SKILL.md` metadata.
- Downloaded MCP code is never executed. Package entries are static evidence, not live runtime proof.
- Codex can scan, inspect, explain a finding, plan hardening, apply selected deterministic JSON cleanup, and verify the result through page tools.
- Any supported write creates a sibling backup first. TOML, commands, policies, and instruction changes stay manual.
- Embedded-browser import is read-only; direct-access browsers can demonstrate apply + verify.

## Current implementation

- `src/codex-analysis.ts` enriches deterministic MCP parsing with artifact, package, instruction-chain, tool-surface, and readiness analysis.
- `src/mcp-files.ts` owns browser permissions, bounded workspace discovery, import fallback, backups, writes, and rescans.
- `src/mcpation.ts` registers nine top-level WebMCP tools with precise schemas and annotations.
- `src/App.tsx` presents the readiness gate, live audit Play/Pause, evidence cards, hardening plan, and scope boundary.
- `demo-workspace/` is a safe, reproducible fixture for recording and judging.
- `scripts/mcpation-tests.ts` covers parsing, redaction, package/instruction discovery, readiness, and tool-input validation.

## Delivery checks

1. Run `npm run verify`.
2. Confirm `https://mcpation.vercel.app/` shows the new Codex Doctor UI and nine tools.
3. Test `demo-workspace` in the browser; never expose personal files in the recording.
4. In direct mode, verify backup/apply/rescan. In read-only mode, keep the honest disabled apply state.
5. Rebuild Graphify after final code/docs changes if the graph is used as an artifact.
6. Commit, push, deploy, and use `DEMO_RUNBOOK.md` + `VIDEO_SCRIPT_EN.md` for the recording.
