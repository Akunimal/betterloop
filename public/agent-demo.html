🪄 MagicPicker — Agent Demo

The capability

MagicPicker is a file handoff, not a file picker. The agent passes the exact path the user requested. The page resolves it without opening a native dialog.

Public tool

{
  "name": "magic_picker_read",
  "description": "Read the exact local file path requested by the user",
  "input": { "path": "src/App.tsx" }
}

Cross-tab tools

{
  "name": "magic_picker_tabs",
  "description": "List safe metadata for tabs in the active browser session"
}
{
  "name": "magic_picker_attach",
  "description": "Prepare an exact file for an HTML upload in a selected tab",
  "input": {
    "path": "C:\\demo\\assets\\logo.png",
    "accept": "image/*",
    "targetTabId": "tab-from-magic_picker_tabs"
  }
}

Call magic_picker_tabs, then magic_picker_attach before continuing the target upload. In Codex the CDP adapter assigns the file directly; in extension mode only that prepared click is intercepted. Normal clicks remain normal.

One-click session

Click Activate MagicPicker — full browser access to give explicit, temporary consent for the local browser bridge. The session ends when this control page closes, navigates away, or you deactivate it. The extension stays dormant outside that session.

Public setup

Open magic-picker.vercel.app and activate the temporary session. For the browser-only demo, optionally click Select project directory and grant access once. The public page uses WebMCP plus the File System Access API.

Local setup

For cross-tab uploads inside Codex, the approved local adapter connects to the embedded Chromium CDP endpoint and keeps the handoff inside that browser session. The MV3 extension remains available for Chromium sessions where extensions are already loaded.

Consent boundary: MagicPicker starts only after the visible Activate button. The adapter does not open an external browser, install software, inspect cookies, or monitor the browser after the temporary session ends.
